# Validation Matrix

The [binding state and recovery](binding-state-flows.md) sequences define the lifecycle behavior behind these checks. Selected policies are requirements to validate, not evidence that runtime integration has passed.

The approved [local Unix socket transport](local-socket-transport.md) defines endpoint ownership, bounded I/O, and connection capacity for the Rust-to-Swift path. The Rust client is reviewed and committed. Bounded source review of the refactored Swift server is complete, and user-provided results confirm the full macOS suite passed on the combined changes. Real-socket interoperability with fake capture and delivery remains deferred.

All supported command paths need checks below, at, and above 30 seconds; successes and failures; suppression of exit status 130; correct exit-status preservation; and completion only after pagers, TUIs, or REPLs exit. Delivery has no sound and no extra threshold delay.

Mac-side eligibility requires `ZED_TERM=true` and no `ZED_NOTIFY_DISABLED=1` opt-out. Verify it at each local command launch and SSH launcher startup before helper startup, source capture, registration, or forwarding. Cover the marker absent or different from `true`, the opt-out applied after shell initialization, and inherited child-shell environments.

Remote notification connections must originate in an eligible regular integrated terminal. Remote hooks require an active bridge association rather than a forwarded `ZED_TERM` variable; unassociated remote shells must not emit bridge notifications. Persistent tmux hooks resolve the session's current route at qualifying completion, allowing delivery after reattachment for a command already running. Verify eligibility separately from source-window attribution.

Check the opt-out flag in new, recreated, and existing Terminal Threads and inherited child shells, while preserving existing initialization commands. Denylist checks must distinguish actual invocations from unrelated mentions in arguments and avoid excluding unrelated commands using shared launchers or Node.

Verify foreground suppression for the exact source window, delivery when another Zed window is foreground, click focus across Spaces, and original source associations after later commands or concurrent connections. Include moved, resized, overlapping, minimized, and closed windows, helper restart or unavailability, local commands without reliable source attribution, remote teardown, and manual reconnect.

Retained public Accessibility objects are the approved identity baseline. Numeric WindowServer IDs, geometry matching, stacking-order matching, and private API conversion are outside this baseline. The Mac-only tests above do not establish end-to-end hook integration or reliable source capture timing.

The user keeps each terminal in its original Zed window for the shell's lifetime; moving live terminals between windows is outside the baseline. Verify independent non-exported caches for child shells, no captures during simultaneous terminal restoration, and new associations for new shells. Reject focus changes detected during capture and timeouts without blocking command execution. The race before the first focus query is an accepted limitation, to revisit if observed in practical use; these safeguards do not eliminate it. Capture must never occur at completion or click.

Verify helper reuse across local shells and SSH connections, continued operation after closing one project window, and continued operation when no windows remain but Zed is still running. Cover Zed exiting during helper setup, termination of the associated app instance, and fresh bindings after relaunch. The existing closed-window probe did not quit Zed or validate helper exit detection.

Verify implicit and explicit manual attachment, attached creation with and without a name, both create-or-attach branches, initial server creation, and direct entry through the same registration path. Context must be published before detachment. Cover the actual native default target, missing or ambiguous targets and failed creation without modifying another session, persistent pane survival, hook availability in existing and new panes, stale context, and independent session routes. Reattachment may change the window used for future completion events; already issued notifications must retain their original associations. Detached creation is not required in the first version.

Background jobs and replay of events completed without an available notification connection are outside the first version. Native OSC 9 is a conditional future note and has no current implementation or validation work.

## Unit-test requirements

Add the applicable tests alongside each implemented component. Unit tests and isolated shell fixtures must verify observable behavior and complete state transitions, including failures, rather than duplicate implementation details. Use controlled clocks and fake transport, process, and window operations; these tests must not require AL2023 access, live macOS notifications, window activation, or real 30-second waits. All applicable automated checks must pass before end-to-end validation of that component.

| Area | Required coverage |
| --- | --- |
| Notification policy | Durations below, exactly at, and above 30 seconds; successful and failed commands; exit status 130 suppression; no extra threshold delay; silent notification content without command text or sensitive paths. |
| Eligibility and exclusions | Required Zed marker, absent or incorrect marker, Terminal Thread opt-out applied after initialization, inherited opt-out, direct harness invocations, supported expanded aliases, configured wrapper names, and ordinary arguments that merely mention harness names. Rejected commands must cause no helper startup, capture, or forwarding. |
| Zsh hook behavior | Capture command status before hook operations alter it; preserve status when capture or sending fails; coexist with existing hooks; notify once at completion; exclude launcher exit, detach, and maintenance actions from command notifications. Exercise hook registration and execution in isolated Zsh processes. |
| Shell binding and recovery | First eligible capture; successful cache reuse with no further client call at launch; failed capture leaving an empty cache; later retry; stale-token clearing; manual rebind of a valid but incorrect association; failed rebind; independent non-exported child-shell caches; no startup capture. Previously launched local commands retain their original tokens. |
| Connection routing and notification identity | Command starts under A and completes after reattachment through B; disconnected completion is dropped without replay; stale routes are rejected; sessions remain independent; remote rebind replaces the current connection association. Already issued notifications retain their original association after reconnect or rebind. |
| Protocol and sender | Valid completion and control messages; malformed, oversized, incomplete, and unsupported messages; control-character handling; unregistered or stale connection identifiers; partial reads and writes; refused or interrupted connections; lost responses and deadline expiry; correct success and failure results. |
| Launcher and cleanup | Construct SSH arguments with correct quoting and the existing alias; establish forwarding within one SSH process; preserve normal and failed SSH results; run cleanup after exit; preserve the SSH result if cleanup fails; defer cleanup while SSH remains running; restore settings changed by the launcher. Reuse selected fake-SSH fixtures where useful. |
| Swift helper logic | Suppress only when the retained source is the focused window of the foreground Zed app; allow notification when another window is foreground; reject invalid sources without selecting another window; replace bindings on rebind without mutating existing notifications; discard associations when the associated Zed app instance exits. Fake native operations for policy and lifecycle tests. |

Unavailable associations skip notification and report recovery guidance. Test first and changed errors, suppressed repeats, reset on success of the affected operation, independent pane diagnostic state, and unconditional manual-rebind results. Distinguish unknown tokens, unavailable sources, and transport failures; a transport timeout alone does not prove token invalidity. Preserve newer ordinary-shell caches and tmux contexts when older requests fail. The accepted initial attribution race remains a documented limitation, not a guarantee that unit tests can establish or eliminate.

Keep actual tmux target selection, SSH forwarding, socket deadline behavior, macOS permissions, cross-Space and minimized-window focus, terminal mouse cleanup, and Linux executable compatibility in integration testing. Mocked outcomes do not establish that these operating-system behaviors work. Native window control and sleep/wake checks remain part of the developer checklist below.

The [local socket checks](local-socket-transport.md#validation) use the production Rust client and Swift server over a real Unix socket. Successful completion must reach the identical fake source object captured during bind. Run the framing, absolute-deadline, disconnect, capacity, endpoint-lifecycle, and pathname checks in that profile. Passing these tests establishes local transport behavior while native capture, notification delivery, helper app lifetime, and remote forwarding remain separate validation.
