# Lightweight Implementation Plan

**Status:** Draft; isolated tmux probes and the Rust/Swift protocol test foundation are complete. Slice 2's bind/completion handler is wired to retained-window capture. The local Unix socket transport's Rust client is reviewed and committed; bounded source review of the refactored Swift server is complete, and user-provided results confirm its full macOS suite passed. Socket interoperability and notification delivery remain.

Build Zed Terminal Command Notifications in small working slices, using the [initial design](initial-design.md) for scope and the [validation matrix](validation-matrix.md) for required behavior and tests. Establish the shared Mac helper and ordinary local command delivery first, add SSH delivery, then integrate persistent local and remote tmux. Revise the order and technical choices as implementation produces evidence.

See the evolving [code layout](code-layout.md) for the proposed source organization and build orchestration.

The [binding state and recovery](binding-state-flows.md) companion expands the selected policies into lifecycle sequences. Missing associations skip notification; diagnostics provide recovery guidance and suppress repeats per shell operation; local tmux continues while detached; and the latest successful eligible attachment selects the session context without automatic fallback.

This plan deliberately stays at the level of working outcomes. Implementation and testing will expose constraints that change task boundaries, interfaces, and sequencing; an exhaustive task list now would become stale and add maintenance without improving the next decision. Elaborate the next slice when it is ready to implement, and revise later slices from what we learn. Scope, required behavior, and validation obligations remain explicit in the linked documents.

The progress column tracks each slice's working result, not a detailed task checklist. A slice is complete when its working result is met; partial evidence or setup is recorded as in progress.

## Iteration and testing

Share tmux attach/create integration, session-context lookup, and completion-time binding semantics. Keep delivery setup and validation specific to the transport: local tmux uses a helper window token and the ordinary local client; remote tmux uses the reverse-forward endpoint and registered SSH connection. Local tmux requires no SSH connection registration. Ordinary local shells retain launch-time tokens, while both tmux paths resolve the current session context at qualifying completion.

Add the applicable unit tests with each slice and pass them before its end-to-end checks. Use controlled clocks, fake SSH/transport/window operations, and isolated Zsh fixtures. Keep real tmux, macOS focus and permissions, socket deadlines, Linux compatibility, and sleep/disconnect checks in integration testing.

At each slice, record what works, what remains uncertain, and any design change before expanding the implementation. Adjust protocol details, CLI spelling, build target, deadlines, and activation delays when their slice makes them concrete. A failed probe should trigger a bounded revision rather than expansion into a general session manager or Zed fork.

Keep reproducible scripts and outcome summaries shareable. Keep raw device-specific evidence and runtime artifacts outside version control; use synthetic data in tests. Retain the accepted initial capture race as a limitation, with manual rebind as recovery. Manual reconnect and the existing exclusions remain the baseline throughout.
